## README.md

Use this as the repository README:

````md
# TechSpace BuildLab '26

> **Learn by Building.**

Official landing website for **TechSpace BuildLab '26** — a two-week,
mentor-supported, project-based learning program by TechSpace, SRM University,
Sonepat.

BuildLab is designed around one simple idea:

**Learn by building real projects.**

Participants choose a track, select or propose a project, write a PRD,
receive mentor approval, and build using a professional GitHub workflow with
Issues, Branches, Pull Requests and Code Reviews.

---

## About BuildLab

TechSpace BuildLab '26 is a project-based learning pilot for SRM University
students from the 1st to 3rd year.

The program begins with an in-person inauguration and then continues online
through GitHub and Discord.

### Program

| | Details |
|---|---|
| Organizer | TechSpace, SRM University, Sonepat |
| Format | Project-based + mentor-supported |
| Duration | 1 October – 15 October 2026 |
| Duration | 2 weeks |
| Inauguration | 1 October 2026, 10:30 AM |
| Venue | Nandi Hall |
| Eligibility | SRM University B.Tech CSE / BCA CS, 1st–3rd year |
| Platforms | GitHub + Discord |
| Cohort | Approximately 40–60 participants |
| Program model | PRD → Mentor Approval → Development → Demo |

---

## Tracks

### Beginner

**Format:** Solo

Designed for students who are new to Git/GitHub or building their first
complete project.

Projects should be small, well-scoped and demonstrate a working solution
with clear documentation.

**Team size:** 1

---

### Intermediate

**Format:** Duo

Designed for students with some project experience and working knowledge of
Git.

Projects should contain multiple features and demonstrate proper division of
work, Pull Requests and cross-review.

**Team size:** 2

---

### Advanced

**Format:** Squad

Designed for students with strong fundamentals, prior project experience and
team-workflow knowledge.

Projects are expected to be more complete and technically ambitious, with
defined team responsibilities and stretch goals.

**Team size:** 3–4

---

## Project Domains

Projects may fall into areas such as:

- Web / Full Stack
- AI / ML
- Backend
- Mobile / App Development
- Systems / DSA
- Automation / Developer Tools

A domain is offered where appropriate mentor support is available.

Participants may either:

1. Choose from the BuildLab project catalogue, or
2. Propose their own project through the PRD process.

---

## How BuildLab Works

```text
Registration
     ↓
Track Selection
     ↓

     ↓
PRD Submission
     ↓
Mentor Review
     ↓
PRD Approval
     ↓
Development
     ↓
Testing & Documentation
     ↓
Final Submission
     ↓
Demo & Evaluation
     ↓
Results
````

### PRD Approval

Every participant or team must submit a Product Requirements Document before
development begins.

The PRD contains:

* Project title
* Track
* Team members
* Problem statement
* Target users
* Core features
* Stretch features
* Technology stack
* Project domain
* Milestones
* Success criteria
* Risks and dependencies

Development begins only after mentor approval.

---

## Development Workflow

BuildLab uses a professional software-development workflow.

```text
Issue
  ↓
Branch
  ↓
Development
  ↓
Commit
  ↓
Pull Request
  ↓
Code Review
  ↓
Merge
```

Every approved project receives a repository within the TechSpace GitHub
Organization.

GitHub is the primary record of project work.

---

## Mentorship

Mentors are assigned by track.

Mentor responsibilities include:

* PRD review and approval
* Weekly project check-ins
* Technical guidance
* Pull Request/code review
* Project scope guidance
* Support through Discord

Mentors guide participants toward solutions rather than writing participant
code.

## Evaluation

Projects are evaluated using six criteria:

| Criterion                        | Points |
| -------------------------------- | -----: |
| Technical Implementation         |     10 |
| GitHub Workflow & Collaboration  |     10 |
| Documentation                    |     10 |
| Innovation / Problem Solving     |     10 |
| Usability / Developer Experience |     10 |
| Consistency & Progress           |     10 |
| **Total**                        | **60** |

Projects are evaluated against their approved PRD.

Evaluation focuses on the quality and authenticity of the work rather than
simply counting commits.
